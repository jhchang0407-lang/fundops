## Problem Statement
The thesis agent is the middle of the FundOps pipeline: Screener (free, finds 20 stocks) → **Thesis (validates the opportunity)** → IC Review (stress-tests) → Memo ($1, full deep dive). The current thesis agent is too shallow: growth-adjusted P/E, two web searches, formulaic return decomposition. It doesn't read SEC filings, isn't strategy-aware, and produces vague narratives. It needs to be good enough that you can read a thesis in 2 minutes and decide "yes, spend $1 on the full memo" or "pass, move on."

## What Makes This Cool
An open-source tool that reads actual SEC 10-K filings, runs web research, adapts its analysis lens to YOUR investment strategy, and writes a real investment thesis with structured scorecard + narrative. Free. Strategy-aware. Runs on 20 stocks in batch. Nothing like this exists as open source.

## Constraints
- **Cost:** ~$0.10-0.15 per ticker (LLM + web search). ~$2-3 for a full batch of 20. Must stay under $5 total.
- **Speed:** 20 tickers should complete in under 5 minutes total (can parallelize).
- **Data sources:** SEC EDGAR (free, already have connector), web search (GPT-5 mini, already have), yfinance (free, already have). No FMP dependency for core flow.
- **Strategy-aware:** The thesis focuses on dimensions from the user's strategy profile. A momentum investor's thesis looks different from a value investor's thesis.
- **Structured output:** Scorecard (quantitative) + narrative (qualitative) in a consistent JSON schema so the frontend can render it cleanly.

## Premises
1. The thesis is a go/no-go gate for spending $1 on a research memo. Good enough to build conviction or kill it.
2. Web search + SEC 10-K filings give enough context for a real thesis. Public information is the foundation.
3. Strategy awareness means the thesis focuses on YOUR dimensions. Same data, different lens.
4. The thesis agent ranks and highlights top 10 from the 20 screener picks. User can override and promote any of the 20 to IC review.

## Approaches Considered

### Approach A: Strategy-Aware Minimal
Add strategy lens to existing ThesisAgent. Same data sources (web + yfinance), LLM prompt adapts to strategy. Ships fast but shallow. No SEC filings.
- Effort: S | Risk: Low | Completeness: 5/10
- Pros: Ships in 30 min, pattern proven with memo agent
- Cons: Still growth-adjusted PE only, no real depth

### Approach B: Deep Thesis + SEC + Strategy (CHOSEN)
Rewrite thesis agent: SEC 10-K filing analysis, strategy-aware LLM narrative, sector-specific valuation, structured scorecard + narrative.
- Effort: M | Risk: Med | Completeness: 9/10
- Pros: Real depth, SEC filings are free gold, best free thesis tool
- Cons: More complex, SEC parsing adds latency

### Approach C: Progressive Depth (Two Tiers)
Tier 1: fast scorecard for all 20. Tier 2: deep thesis auto on top 10.
- Effort: M-L | Risk: Med | Completeness: 8/10
- Pros: Fast results + depth where it matters
- Cons: Two code paths, UX complexity

## Recommended Approach

**Approach B: Deep Thesis with SEC + Strategy.**

### Architecture

```
ThesisAgent.run(context={"ticker": "AAPL", "strategy": {...}})
  │
  ├── Phase 1: Data Collection (parallel)
  │   ├── yfinance: price, market cap, PE, sector, basic metrics
  │   ├── SEC EDGAR: latest 10-K (existing connector, build_agent_context)
  │   └── Web search: "why is AAPL cheap?" + bull/bear catalysts
  │
  ├── Phase 2: Strategy Lens Construction
  │   ├── Read active strategy from DB (or context)
  │   ├── Build strategy_lens directive (same pattern as memo agent)
  │   └── Determine which dimensions to score and emphasize
  │
  ├── Phase 3: Valuation (deterministic, no LLM)
  │   ├── Sector-specific model selection:
  │   │   ├── Tech/SaaS: growth-adjusted DCF
  │   │   ├── Financials: P/TBV + ROE-based
  │   │   ├── REITs: NAV-based
  │   │   ├── Utilities: DDM
  │   │   └── General: normalized earnings + peer multiples
  │   ├── 3-year revenue/earnings trend from SEC data
  │   ├── Fair value estimate with confidence range (low/mid/high)
  │   └── Return decomposition: discount + growth + margin + dividends
  │
  ├── Phase 4: LLM Thesis Generation (structured output)
  │   ├── System prompt includes: strategy lens + financial data + SEC context + web research
  │   ├── Structured JSON output (not free-form):
  │   │   ├── opportunity_summary: 2-3 sentences on why this opportunity exists
  │   │   ├── variant_view: what the market is missing
  │   │   ├── bull_case: specific catalysts and upside scenario
  │   │   ├── bear_case: specific risks and downside scenario
  │   │   ├── key_question: the ONE thing you'd need to verify in a full memo
  │   │   └── conviction: HIGH/MEDIUM/LOW with one-line reasoning
  │   └── Cost: ~$0.05-0.10 per ticker (GPT-5 mini, medium reasoning)
  │
  └── Phase 5: Scorecard Assembly
      ├── Strategy dimension scores (from data, not LLM):
      │   ├── Each dimension from the user's strategy gets a 0-10 score
      │   ├── Uses the same metric access as the screener
      │   └── Dynamic: a momentum strategy scores momentum/volume/catalyst
      ├── Valuation score: based on discount to fair value
      ├── Thesis quality score: conviction + evidence strength
      └── Overall thesis score: weighted composite for ranking
```

### Strategy-Aware Dimensions

The scorecard section is **dynamic** — whatever dimensions the user's strategy has, those become the scorecard rows. Just like the screener's `label_map` determines columns, the thesis scorecard adapts:

| Strategy Type | Scorecard Dimensions |
|--------------|---------------------|
| Value/Compounder | Cheapness, Quality, Growth, Margin Trend |
| Momentum | Trend Strength, Volume, Catalyst Timeline, Risk/Reward |
| Turnaround | Discount to Distressed Value, Management Change, Balance Sheet |
| Income | Dividend Yield, Payout Sustainability, Earnings Stability |

## Error Handling & Fallbacks

| Failure | Behavior |
|---------|----------|
| SEC 10-K not found (foreign filer, recent IPO) | Fall back to 10-Q or 20-F. If none, run thesis without filing context. Flag `sec_available: false` in output. |
| Web search timeout or error | Run thesis with financial data + SEC only. Web research fields return empty strings. |
| yfinance returns no data | Skip ticker entirely. Log error. Batch returns N-1 results. |
| LLM call fails | Retry once. If still fails, return scorecard without narrative. `narrative: null`. |
| Partial batch failure | Return all successful results. Failed tickers listed in `failed` array with error messages. Frontend shows "15/20 completed, 5 failed" with retry option. |

### SEC Rate Limiting
SEC EDGAR allows 10 requests/second with a User-Agent header. Use an asyncio semaphore limiting to 8 concurrent SEC requests. Each 10-K fetch + parse takes ~5-8 seconds. With 8 concurrent: 20 tickers completes in ~15-20 seconds.

```python
SEC_SEMAPHORE = asyncio.Semaphore(8)
async def fetch_sec_throttled(ticker):
    async with SEC_SEMAPHORE:
        return await sec.get_filing(ticker, "10-K")
```

### Scoring Methodology

Each strategy dimension maps to a 0-10 score using `normalize(value, low, high)` from the scoring sandbox. The same normalization ranges used by the screener apply:

| Dimension | Metric | Low (0) | High (10) |
|-----------|--------|---------|-----------|
| Cheapness | PE relative to sector median | 2x above | 0.5x below |
| Quality (margins) | Gross margin | 20% | 70% |
| Quality (ROIC) | ROIC | 5% | 30% |
| Growth | 3yr revenue CAGR | 0% | 25% |
| Momentum | 6-month price change | -20% | +40% |
| Dividend | Yield | 0% | 5% |

Only the dimensions present in the user's strategy appear in the scorecard. The `thesis_score` is the weighted average using the same weights as the screener scoring function (extracted from the strategy profile's agent_defaults).

### Valuation Assumptions
All valuation assumptions are **deterministic and sector-driven**, not LLM-generated:
- **WACC:** Fixed 10% for most sectors. 8% for utilities. 12% for small-cap/high-risk.
- **Terminal growth:** 2.5% (GDP proxy).
- **Growth rate:** Derived from 3-year revenue CAGR from SEC filings, capped at 20%.
- **Fair PE:** Sector median PE from the screener's sector_medians calculation.

### SEC Context Structure
The `sec_context` field contains:
```json
{
  "filing_type": "10-K",
  "filing_date": "2025-11-01",
  "key_excerpts": [
    {"section": "Risk Factors", "text": "first 500 chars..."},
    {"section": "MD&A", "text": "first 500 chars..."},
    {"section": "Business Description", "text": "first 500 chars..."}
  ],
  "available": true
}
```
Both raw excerpts AND the LLM synthesis are stored. The user can expand to read the raw SEC text in the frontend. The LLM synthesis appears in the narrative sections.

### Persistence
Thesis results are persisted to the `agent_runs` table via `db.record_run("thesis", ...)`. Dismiss actions are persisted to the same `screener_feedback` table used by the screener, with `stage: "thesis"` to distinguish.
