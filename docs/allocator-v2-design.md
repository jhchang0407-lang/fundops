## Problem Statement

The Allocator is the brain of FundOps. It takes two inputs (portfolio health signals + new research opportunities) and outputs one thing: what portfolio moves to make. The current AllocatorAgent is barebones, just checking concentration limits and thesis breaches. The CLI vanguard_allocator.py is 1200 lines of hardcoded value-investor rules. Neither consumes the Library opportunity pipeline, neither is strategy-aware, and neither can answer the most important question: "is this new opportunity better than my weakest position?"

Without the Allocator working properly, the entire pipeline ends at "here's a memo." The user is left to manually compare opportunities against held positions, apply their own sizing logic, and make decisions without systematic support. The Allocator closes the loop.

## What Makes This Cool

The Allocator is a portfolio compiler. You define your target portfolio as a specification through the strategy conversation: "I want 60% quality compounders, 20% dislocations, 20% optionality. Max 12 positions. 20% minimum portfolio-level expected return." The Allocator treats your current portfolio as source code and the spec as the compilation target. Every cycle, it computes the diff and emits atomic moves to get you closer.

The killer feature: you can ask "what would my portfolio look like if I changed my strategy from value to growth compounder?" and the Allocator re-compiles without touching anything. Strategy becomes a query language for portfolios.

And the AI writes the rules. Same pattern as the Screener. The strategy conversation generates deterministic allocation code (AllocationSpec). The rules handle the math. The LLM handles the qualitative reasoning for swap comparisons. Three layers: AI-generated rules → deterministic execution → AI narrative on top.

## Constraints

- **Inputs:** Portfolio Monitor's `AllocatorFeed` (position health, decay, conviction, weakest positions) + Library's IC-passed memos (opportunity pipeline with expected returns).
- **No auto-trading.** Recommendations only. The user confirms every move.
- **Strategy-driven.** All allocation rules come from the strategy conversation. No hardcoded thresholds.
- **Cost:** The deterministic engine (rules) is free. The LLM narrative for swap comparisons is ~$0.05-0.10 per comparison. Running the allocator on 14 positions with 5 swap candidates = ~$0.50-1.00.
- **Dependencies:** Portfolio Monitor v2 and Library v2 must be producing data for the Allocator to work meaningfully.
- **Tax awareness.** Must consider holding period (short-term vs long-term capital gains) in trim recommendations.

## Premises

1. The Allocator consumes two inputs: Portfolio health + Library opportunities. Compares and recommends.
2. AI writes allocation rules from strategy. Rules handle the math deterministically.
3. AI handles qualitative comparison reasoning (swap X for Y?). LLM reads both theses and explains.
4. Recommends, never executes. User decides.
5. Strategy determines everything about allocation style. No hardcoded value-investor assumptions.
6. Capstone agent. Depends on Portfolio Monitor + Library + Memo.

## Recommended Approach

**Approach B: Portfolio Compiler with Swap Logic.**

AI generates AllocationSpec from strategy. Deterministic engine computes the diff between current portfolio and target. Consumes AllocatorFeed + Library opportunities. LLM narrates swap reasoning. Tax-aware transitions.

### Architecture

#### 1. AllocationSpec (the intermediate representation)

The AllocationSpec is what the AI generates from the strategy conversation. It's the "compiled" version of the strategy, stored in the DB, and consumed by the deterministic engine.

```python
class AllocationSpec(BaseModel):
    """The compiled allocation rules, generated by AI from strategy."""

    # ── Portfolio shape ──
    target_positions: int         # e.g. 10-15
    max_positions: int            # hard cap
    min_positions: int            # floor (avoid too concentrated)

    # ── Position type targets ──
    position_types: dict[str, PositionTypeSpec]
    # e.g. {"core_compounder": {target_weight: 60, max_per_position: 10},
    #        "dislocation": {target_weight: 20, max_per_position: 7},
    #        "optionality": {target_weight: 20, max_per_position: 5}}

    # ── Concentration limits (with validation bounds) ──
    max_single_position_pct: float = Field(ge=3, le=30)
    top3_max_pct: float = Field(ge=20, le=70)
    top5_max_pct: float = Field(ge=30, le=85)
    max_theme_overlap_pct: float = Field(ge=10, le=50)

    # ── Return hurdles ──
    min_portfolio_expected_return_pct: float = Field(ge=5, le=40)
    min_position_expected_return_pct: float = Field(ge=5, le=30)
    # Note: per-position floor (e.g. 12%) is intentionally below the IC entry hurdle (20%)
    # because positions decay over time. This is the point at which the allocator flags for review.
    swap_threshold_pct: float = Field(ge=2, le=25)

    # ── Thesis health triggers ──
    decay_trim_threshold: float = Field(le=0)  # negative number, e.g. -3.0 = 3 pts/week decline triggers review
    health_exit_threshold: int = Field(ge=0, le=50)  # health score below which exit recommended
    breach_action: str               # "review" | "trim" | "exit" (when assumption breaches)

    # ── Tax awareness ──
    prefer_long_term_gains: bool     # hold 1yr+ before trimming when possible
    tax_drag_threshold_pct: float    # min expected return improvement to justify short-term trim

    # ── Strategy-specific rules (deferred to v3) ──
    # custom_rules_code: str | None  # deferred: AI-generated Python for strategy-specific logic
    # Interface TBD. AllocationSpec fields cover known use cases for v2.

class PositionTypeSpec(BaseModel):
    target_weight_pct: float      # target allocation to this type
    max_per_position_pct: float   # max weight for any single position of this type
    min_conviction: int           # minimum conviction to hold (1-5)
    hold_horizon: str             # "1-2yr" | "3-5yr" | "5yr+"
    sizing_logic: str             # "equal_weight" | "conviction_weighted" | "return_weighted"
```

#### 2. Strategy-to-Spec Compiler

The AI generates an AllocationSpec from the strategy conversation. Same pattern as screener scoring code.

```python
STRATEGY_TO_SPEC_PROMPT = """Given this investor's strategy profile, generate their allocation specification.

Strategy: {north_star}
Dimensions: {dimensions}
Current portfolio context: {portfolio_summary}

Generate an AllocationSpec that encodes how this investor should size and manage positions.

Rules:
- Position types should map to the strategy's thesis buckets
- Concentration limits should reflect the strategy's conviction style
  (concentrated value = higher single-position max, diversified growth = lower)
- Return hurdles should align with the strategy's target return
- Swap threshold determines how much better a new opp must be to justify replacing a held position
  (conservative strategies = higher threshold, aggressive = lower)
- Tax awareness should match the strategy's time horizon
  (3-5yr = always prefer long-term gains, <1yr = tax is less relevant)

Return a structured AllocationSpec."""

async def strategy_to_spec(north_star: str, dimensions: dict,
                           portfolio_summary: dict) -> AllocationSpec:
    result = await llm.generate(
        prompt=STRATEGY_TO_SPEC_PROMPT.format(
            north_star=north_star,
            dimensions=json.dumps(dimensions),
            portfolio_summary=json.dumps(portfolio_summary),
        ),
        response_format=AllocationSpec,
        reasoning_effort="high",
    )
    return result.parsed
```

#### 3. The Deterministic Engine

The core allocation logic. No LLM calls. Pure Python constraint evaluation.

```python
class AllocationEngine:
    """Computes portfolio diff from current state to target spec."""

    def __init__(self, spec: AllocationSpec):
        self.spec = spec

    def compute_recommendations(
        self,
        portfolio_feed: AllocatorFeed,
        opportunities: list[LibraryOpportunity],
    ) -> AllocationResult:
        """Deterministic: compare current portfolio against spec, emit moves."""

        moves = []

        # Phase 1: Position management (held positions)
        for pos in portfolio_feed.positions:
            move = self._evaluate_position(pos)
            if move:
                moves.append(move)

        # Phase 2: Concentration check
        concentration_moves = self._check_concentration(portfolio_feed)
        moves.extend(concentration_moves)

        # Phase 3: Swap evaluation (weak positions vs opportunities)
        swap_candidates = self._find_swap_candidates(
            portfolio_feed.weakest_positions,
            opportunities,
        )
        moves.extend(swap_candidates)

        # Phase 4: New position evaluation (if cash available or after trims)
        new_position_candidates = self._evaluate_new_positions(
            portfolio_feed, opportunities, moves
        )
        moves.extend(new_position_candidates)

        # Phase 5: Portfolio-level checks
        portfolio_checks = self._portfolio_level_checks(portfolio_feed, moves)
        moves.extend(portfolio_checks)

        return AllocationResult(
            moves=self._rank_and_dedupe(moves),
            portfolio_diff=self._compute_diff(portfolio_feed, moves),
            spec_compliance=self._check_spec_compliance(portfolio_feed),
        )

    def _evaluate_position(self, pos: PositionHealth) -> PortfolioMove | None:
        """Evaluate a single held position against the spec."""

        # Exit: thesis health below exit threshold
        if pos.thesis_health < self.spec.health_exit_threshold:
            return PortfolioMove(
                action="EXIT",
                ticker=pos.ticker,
                urgency="high",
                math_reason=f"Thesis health {pos.thesis_health}/100 below exit threshold {self.spec.health_exit_threshold}",
                current_weight=pos.weight,
                target_weight=0,
            )

        # Trim: concentration above max
        type_spec = self.spec.position_types.get(pos.position_type)
        if type_spec and pos.weight > type_spec.max_per_position_pct:
            return PortfolioMove(
                action="TRIM",
                ticker=pos.ticker,
                urgency="medium",
                math_reason=f"Weight {pos.weight:.1f}% > {type_spec.max_per_position_pct}% max for {pos.position_type}",
                current_weight=pos.weight,
                target_weight=type_spec.max_per_position_pct,
                tax_consideration=self._tax_check(pos),
            )

        # Review: thesis decaying (both are negative; more negative = worse)
        # decay_rate: -5 pts/week is worse than -3 pts/week
        # threshold: -3 means "trigger if decay is -3 or worse"
        if pos.decay_rate <= self.spec.decay_trim_threshold:
            return PortfolioMove(
                action="REVIEW",
                ticker=pos.ticker,
                urgency="medium",
                math_reason=f"Thesis decay {pos.decay_rate:.1f} pts/week (threshold: {self.spec.decay_trim_threshold})",
            )

        # Breach: assumption violated (from Portfolio Monitor alerts)
        if pos.breached_assumptions and self.spec.breach_action != "hold":
            return PortfolioMove(
                action=self.spec.breach_action.upper(),  # "REVIEW" | "TRIM" | "EXIT"
                ticker=pos.ticker,
                urgency="medium",
                math_reason=f"Assumption breach: {', '.join(pos.breached_assumptions[:2])}",
            )

        return None  # HOLD

    def _find_swap_candidates(
        self,
        weak_positions: list[WeakPosition],
        opportunities: list[LibraryOpportunity],
    ) -> list[PortfolioMove]:
        """Compare weak positions against available opportunities."""
        swaps = []

        for weak in weak_positions:
            # Find opportunities that would be better
            for opp in opportunities:
                return_improvement = opp.expected_return - weak.expected_return
                if return_improvement >= self.spec.swap_threshold_pct:
                    swaps.append(PortfolioMove(
                        action="SWAP",
                        ticker=weak.ticker,
                        swap_for=opp.ticker,
                        urgency="medium",
                        math_reason=(
                            f"{opp.ticker} expected return {opp.expected_return:.0f}% vs "
                            f"{weak.ticker} {weak.expected_return:.0f}% "
                            f"(+{return_improvement:.0f}% improvement, "
                            f"threshold: {self.spec.swap_threshold_pct}%)"
                        ),
                        current_weight=weak.weight,
                        target_weight=weak.weight,  # same weight, different ticker
                        tax_consideration=self._tax_check_swap(weak, opp),
                        needs_narrative=True,  # flag for LLM comparison
                    ))

        return swaps
```

**Input schema references:**
- `AllocatorFeed` and `PositionHealth`: defined in Portfolio Monitor v2 design (portfolio-monitor-v2-design.md, section 6)
- `WeakPosition`: defined in Portfolio Monitor v2 design (section 6)
- `LibraryOpportunity`: an IC-passed memo from Library with `ticker`, `expected_return`, `thesis_summary`, `ic_verdict`, `assumptions`, `fair_value`

**Dedup priority rules:** When multiple phases recommend actions on the same ticker, priority order: EXIT > SWAP > TRIM > REVIEW > ADD > HOLD. Higher-priority action wins. Example: Phase 1 says REVIEW (decaying thesis), Phase 3 says SWAP (better opportunity available). SWAP wins because it's higher priority and subsumes the REVIEW concern.

**Position type assignment:** Position types are assigned by the user through the strategy conversation or portfolio import. Each position in `AllocatorFeed` carries a `position_type` field. If unassigned, defaults to "core". The strategy conversation can bulk-assign types: "RCAT and UMAC are optionality plays."

**Tax sequencing limitations (v2):** Holding-period-only. Does not handle lot-level selection, wash sale 30-day windows, or net gain/loss optimization at the portfolio level. These are deferred.

#### 5. Portfolio Diff and Spec Compliance

The engine computes what the portfolio looks like after proposed moves and checks it against the spec.

```python
class AllocationResult(BaseModel):
    moves: list[PortfolioMove]         # ranked by impact
    portfolio_diff: PortfolioDiff      # before/after comparison
    spec_compliance: SpecCompliance    # how well current portfolio matches spec

class PortfolioDiff(BaseModel):
    before: PortfolioSnapshot
    after: PortfolioSnapshot           # if all moves are executed
    expected_return_change: float      # portfolio-level return change
    concentration_change: float        # top position weight change
    type_allocation_change: dict       # per-type weight change
    theme_overlap_change: float

class SpecCompliance(BaseModel):
    """How well the current portfolio matches the AllocationSpec."""
    overall_score: int                 # 0-100
    position_count_ok: bool
    type_allocation_ok: dict[str, bool]  # per-type within target?
    concentration_ok: bool
    return_hurdle_ok: bool
    theme_overlap_ok: bool
    violations: list[str]              # specific spec violations

class PortfolioMove(BaseModel):
    action: str              # "TRIM" | "ADD" | "SWAP" | "EXIT" | "HOLD" | "REVIEW" | "NEW_POSITION"
    ticker: str
    swap_for: str | None     # ticker to swap into (SWAP only)
    urgency: str             # "high" | "medium" | "low" | "none"
    math_reason: str         # deterministic explanation
    narrative: SwapNarrative | None  # LLM reasoning (for swaps)
    current_weight: float | None
    target_weight: float | None
    tax_consideration: str | None
    needs_narrative: bool = False
```

#### 6. "What If" Recompilation

The user can ask "what would my portfolio look like with a different strategy?" without changing anything.

```python
async def what_if(new_strategy: dict, current_portfolio: AllocatorFeed,
                  opportunities: list[LibraryOpportunity]) -> AllocationResult:
    """Recompile the portfolio against a hypothetical strategy."""
    # Generate new spec from hypothetical strategy
    hypothetical_spec = await strategy_to_spec(
        new_strategy["north_star"],
        new_strategy["dimensions"],
        _summarize_portfolio(current_portfolio),
    )

    # Run the engine with the hypothetical spec
    engine = AllocationEngine(hypothetical_spec)
    result = engine.compute_recommendations(current_portfolio, opportunities)

    # Add comparison annotation
    result.what_if_note = (
        f"If you switched to this strategy, {len(result.moves)} moves would be recommended. "
        f"Portfolio expected return would change from {current_return}% to {result.portfolio_diff.after.expected_return}%."
    )

    return result
```

#### 7. Tax-Aware Transition Sequencing

When the engine recommends multiple moves, sequence them tax-efficiently.

```python
def sequence_moves(moves: list[PortfolioMove], holdings: list[dict]) -> list[SequencedMove]:
    """Order moves to minimize tax impact."""
    sequenced = []

    for move in moves:
        holding = _find_holding(holdings, move.ticker)
        if not holding:
            sequenced.append(SequencedMove(move=move, sequence=0, tax_note="New position"))
            continue

        days_held = (today - parse_date(holding["purchase_date"])).days
        is_long_term = days_held >= 365

        if move.action in ("TRIM", "EXIT", "SWAP"):
            if is_long_term:
                sequenced.append(SequencedMove(
                    move=move, sequence=0,
                    tax_note=f"Long-term gain (held {days_held} days). Tax-efficient to trim.",
                ))
            else:
                days_until_lt = 365 - days_held
                sequenced.append(SequencedMove(
                    move=move, sequence=1,  # lower priority
                    tax_note=f"Short-term gain (held {days_held} days). "
                             f"Long-term in {days_until_lt} days. "
                             f"Consider waiting unless urgency is high.",
                ))

    # Sort: long-term trims first, then new positions, then short-term trims
    return sorted(sequenced, key=lambda s: s.sequence)
```

#### 11. Error Handling

- **No portfolio data:** "Import your portfolio first." Link to Settings.
- **No Library opportunities:** Engine runs position management only (no swaps). Note: "No IC-passed opportunities available for comparison."
- **LLM narrative fails:** Show the math-only recommendation. Flag "narrative unavailable."
- **Stale data:** If portfolio prices are >24h old, show warning. If thesis health is >14 days old, flag.
- **AllocationSpec not generated yet:** "Run the strategy conversation first to generate your allocation rules."

#### 12. Scheduling

- **`allocator-on-memo`**: Triggered when a new memo passes IC review. Re-runs the allocator with the new opportunity in the comparison set.
- **`allocator-weekly`**: Weekly (Monday morning). Full portfolio analysis with latest health signals.
- **Manual trigger:** POST `/allocator/run` from the UI.

## Open Questions

1. **Partial swaps.** The current design has binary swap/hold. Should the engine recommend "trim PAYC by 50%, use proceeds to buy FISV" as a distinct action? (Yes, probably. The UI mockup shows it.)
2. **Cash management.** The spec doesn't explicitly model cash allocation. Should it? "Maintain 5-10% cash for opportunistic adds" is a common strategy rule.
3. **Correlation/overlap detection.** Beyond theme overlap, should the engine detect correlation between positions (both down 15% on the same day = probably correlated)? Defer or include?

## Success Criteria

- AllocationSpec generated from strategy conversation produces reasonable rules for 3+ strategy types
- Deterministic engine correctly identifies concentration violations, thesis breaches, and swap candidates
- LLM narrative explains swap logic in the investor's strategy language
- "What if" recompilation produces different recommendations for different strategies on the same portfolio
- Tax-aware sequencing correctly prioritizes long-term gains over short-term
- Spec compliance score accurately reflects how well the portfolio matches the target
- All recommendations are actionable: clear action, clear reasoning, clear target
