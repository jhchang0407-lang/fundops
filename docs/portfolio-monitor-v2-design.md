## Problem Statement

The portfolio monitor is disconnected and thin. There's a working CLI (pulse_monitor.py) that tracks P&L and generates alerts, a thesis_registry.json with per-position thesis details, a barebones PortfolioAgent backend, and a basic Portfolio.tsx table. But none of it connects: thesis health isn't visible alongside P&L, there's no web research checking if assumptions still hold, the CSV import has no UI, alerts are CLI-only, and nothing feeds the allocator.

The portfolio monitor is the sensor array for the entire FundOps decision engine. Without it working properly, the allocator has no signal for "this position is weakening" and can't compare held positions against new opportunities from the research pipeline.

## What Makes This Cool

Your portfolio monitor doesn't just track how much money you're making. It tracks whether your REASONS for owning each stock are still true. Every position has a thesis with specific assumptions ("CHKP subscription growth stays above 11%"). The monitor checks each assumption against reality every week using financial data + web search, and shows you a decay curve: not just "thesis intact" or "thesis broken," but the slope of conviction eroding. A position where 3 of 5 assumptions are trending negative is very different from one where 1 flipped red overnight.

And like every other FundOps agent, the monitoring lens adapts to your strategy. A value investor's health check for the same stock looks different from a momentum investor's.

## Constraints

- **Price data:** End-of-day closing prices from yfinance (free) or FMP. Not real-time. Updated daily after market close.
- **Thesis health check cost:** ~$0.10-0.20/position/week for web search + LLM scoring. 14 positions = ~$1.40-2.80/week.
- **Data entry:** CSV import from broker (Schwab, Fidelity, etc.) + thesis entry through strategy conversation or per-position form.
- **Existing code:** pulse_monitor.py (CLI), thesis_health.py (CLI), PortfolioAgent (backend), portfolio_routes.py (API), Portfolio.tsx (frontend). All reusable.
- **Schedule:** Daily price/P&L (cheap API calls, no LLM). Weekly thesis health (LLM + web search). On-demand full check.
- **Allocator feed:** Health signals must output in a format the allocator can consume for position-vs-opportunity comparison.

## Premises

1. P&L tracking and thesis health are both required, displayed together in one view.
2. CSV import from broker is the primary data entry. Thesis entered separately via conversation or form.
3. Thesis health is the core differentiator: checking specific assumptions against reality.
4. Strategy shapes what "healthy" means. Same position, different health lens per investor type.
5. The monitor feeds the allocator. Health signals flow downstream for swap/hold recommendations.
6. End-of-day prices, not real-time. Daily P&L check, weekly thesis health. User controls cadence.

## Approaches Considered

### Approach A: Thesis Health MVP
Health dashboard only. Per-assumption scores, colored bars, CSV import UI. No strategy lens, no decay, no allocator.
- Effort: M | Risk: Low | Completeness: 7/10
- Con: Too thin. No strategy awareness, no closed loop.

### Approach B: Full Monitor + Strategy + Decay (CHOSEN)
Complete system: strategy-shaped health lens, per-assumption decay scores with sparklines, web search for thesis validation, CSV import with multi-broker support, and allocator output.
- Effort: L | Risk: Med | Completeness: 9/10
- Pro: Complete closed-loop system. Thesis decay is genuinely new. Strategy-aware from day one.

### Approach C: Real-time Streaming
Everything in B + WebSocket live updates + mobile push.
- Effort: XL | Risk: High | Completeness: 10/10
- Con: Over-engineering. Portfolios are checked 1-2x/day, not real-time.

## Recommended Approach

**Approach B: Full Monitor with Strategy-Aware Thesis Health + Decay Tracking.**

End-of-day prices. Weekly thesis health checks. Decay sparklines. Allocator feed. Strategy lens. No real-time, no mobile push.

#### 1b. Thesis Entry Flow

Three paths to create a thesis for a position. All produce the same `PositionThesis` object.

**Path 1: Import from pipeline (primary).** When a stock passes through Val → Judge → Memo, the thesis is auto-generated from the IC Review output. The Judge's `what_must_be_true` and `key_assumptions` map directly to `ThesisAssumption` objects with categories pre-assigned.

**Path 2: Conversation (manual).** User says in the strategy chat: "I bought CHKP because it's a cheap cash cow with strong buybacks." The AI extracts a structured thesis with assumptions, assigns categories, and saves. Same conversational refinement pattern as the memo profile.

**Path 3: Form (quick add).** Settings UI has a per-position "Add thesis" form:
- Why you own it (free text)
- Key assumptions (list of strings, AI auto-categorizes)
- What breaks it (list of strings)
- Conviction (1-5 slider)

Positions without a thesis still show P&L. They just don't have health scores. The UI shows "Add thesis to enable health monitoring" as a prompt.

#### 1c. CSV Re-Import Merge Logic

```python
async def merge_import(new_holdings: list[dict], db) -> MergeResult:
    """Merge new CSV import with existing positions."""
    existing = {p["ticker"]: p for p in db.get_current_holdings()}
    result = MergeResult(added=[], updated=[], closed=[], unchanged=[])

    for h in new_holdings:
        ticker = h["ticker"]
        if ticker not in existing:
            result.added.append(h)
        elif h["shares"] != existing[ticker]["shares"] or h["cost_basis"] != existing[ticker]["cost_basis"]:
            result.updated.append(h)
        else:
            result.unchanged.append(ticker)

    # Positions in existing but NOT in new CSV = potentially closed
    for ticker in existing:
        if ticker not in {h["ticker"] for h in new_holdings}:
            result.closed.append(ticker)

    return result
    # Frontend shows preview: "Adding 2, updating 1, closing 3, unchanged 8"
    # User confirms before applying. Closed positions are marked "closed", not deleted.
    # Thesis and health history are preserved for closed positions.
```

#### 3. Thesis Health Engine

The thesis health engine is the core of the monitor. It runs weekly (configurable) per position.

```python
class ThesisHealthEngine:
    """Checks thesis assumptions against reality."""

    def __init__(self, llm, web_search, fmp, yfinance, strategy: dict | None):
        self.llm = llm
        self.web_search = web_search
        self.fmp = fmp
        self.yfinance = yfinance
        self.strategy = strategy

    async def check_position(self, ticker: str, thesis: PositionThesis) -> ThesisHealthResult:
        """Run a full thesis health check for one position."""

        # Step 1: Gather current data
        financials = await self._fetch_financials(ticker)
        news = await self._search_news(ticker, thesis)

        # Step 2: Score each assumption
        assumption_scores = []
        for assumption in thesis.assumptions:
            score = await self._score_assumption(
                ticker, assumption, financials, news, self.strategy
            )
            assumption_scores.append(score)

        # Step 3: Calculate overall health (weighted by strategy)
        overall = self._weighted_health(assumption_scores, self.strategy)

        # Step 4: Compare to previous snapshot for trend
        trend = self._calculate_trend(ticker, overall)

        return ThesisHealthResult(
            ticker=ticker,
            overall_health=overall,
            assumption_scores=assumption_scores,
            trend=trend,
            events=self._extract_events(news),
        )
```

**Assumption scoring prompt (structured output):**

```python
SCORE_ASSUMPTION_PROMPT = """You are a buy-side analyst checking whether an investment assumption still holds.

Position: {ticker} ({company})
Assumption: "{assumption_description}"
Metric to check: {metric} (threshold: {threshold})

Current financial data:
{financials_context}

Recent news (last 30 days):
{news_context}

{strategy_lens}

Previous score: {previous_score}/100 (from {previous_date})
Previous evidence: {previous_evidence}

IMPORTANT: Your score must be anchored to the previous score.
- If nothing material changed, your score should be within 5 points of the previous.
- If something material changed, explain WHAT changed and justify the delta.
- Changes > 15 points require specific, concrete evidence (a number, an event, a filing).
- Direction must be justified: "declining" requires evidence WORSE than last check.

Score this assumption 0-100:
- 100: Fully intact, evidence supports it strongly
- 75: Mostly intact, minor concerns
- 50: Mixed signals, could go either way
- 25: Weakening materially, evidence turning negative
- 0: Broken, evidence clearly contradicts the assumption

Return a structured AssumptionScore."""

class AssumptionScore(BaseModel):
    key: str
    score: int              # 0-100
    previous_score: int     # what it was last time (for delta tracking)
    delta: int              # score - previous_score
    delta_justification: str  # why the score changed (required if |delta| > 5)
    trend: str              # "improving" | "stable" | "declining" | "broken"
    evidence: str           # one-line summary of what moved the score
    data_points: list[str]  # specific numbers/facts
    confidence: str         # "high" | "medium" | "low"
```

**Score stability guardrails:** LLMs produce inconsistent numeric scores across runs. The design mitigates this:
1. **Anchoring:** Every scoring prompt includes the previous score + evidence. The LLM must justify deviations.
2. **Delta constraints:** Changes > 15 points require `delta_justification` with specific evidence. The backend validates this.
3. **Two-pass scoring for first-time checks:** First check has no anchor, so run twice and average.
4. **Trend smoothing:** The `trend` field uses a 3-check rolling window, not a single-check comparison.

**Web search provider:** GPT-5 mini with web search enabled (same as Val agent, already configured). Cost: ~$0.02-0.05 per search. One search per position per health check, not per assumption.

**Cost estimate (itemized for 15 positions/week):**
- Web search: 15 positions x $0.03 = $0.45
- LLM scoring: 15 positions x ~5 assumptions x $0.02/assumption = $1.50
- Total per weekly check: ~$1.95
- Monthly: ~$7.80

```python
        "customer_metrics": 1.5,      # NRR, cohort retention

def _weighted_health(self, scores: list[AssumptionScore], strategy: dict) -> int:
    """Calculate overall health, weighted by strategy importance."""
    if not strategy:
        return int(sum(s.score for s in scores) / len(scores))

    weights = self._get_strategy_weights(strategy)
    weighted_sum = 0
    weight_total = 0
    for score in scores:
        w = weights.get(self._classify_assumption(score.key), 1.0)
        weighted_sum += score.score * w
        weight_total += w

    return int(weighted_sum / weight_total) if weight_total > 0 else 50
```

**What the LLM focuses on in the scoring prompt:**
The `{strategy_lens}` in the scoring prompt comes from the strategy profile, same pattern as the memo's `_build_strategy_lens()`:
- Value: "Pay special attention to whether the margin of safety is intact. Is the discount to fair value holding or shrinking?"
- Momentum: "Focus on whether the price trend is intact. Are estimates still being revised upward?"
- Growth: "Watch for any signs of growth deceleration. Are customer metrics still expanding?"

**Decay curve calculation:**
```python
def calculate_decay_rate(history: list[HealthSnapshot], days: int = 30) -> float:
    """Calculate the rate of thesis health decline over N days.

    Returns: negative number = decaying, positive = improving, 0 = stable.
    Expressed as health points per week.
    """
    if len(history) < 2:
        return 0.0
    recent = [h for h in history if h.date >= (today - timedelta(days=days))]
    if len(recent) < 2:
        return 0.0
    # Simple linear regression on health scores over time
    slope = _linear_regression_slope(
        [(h.date, h.overall_health) for h in recent]
    )
    return round(slope * 7, 1)  # points per week
```

**Dashboard sparkline:** Each position row in Portfolio.tsx gets a tiny sparkline chart showing the last 8-12 thesis health checks. Green if stable/improving, yellow if slowly declining, red if rapidly declining.

#### 11. Error Handling

- **FMP/yfinance down:** Use cached prices from last successful fetch. Show "prices as of [date]" indicator.
- **Web search fails:** Score assumptions based on financial data only. Flag confidence as "low" for those checks.
- **LLM fails for one assumption:** Score it as 50 (neutral) with a "check failed" note. Don't block the rest.
- **CSV parse errors:** Show per-row errors, import valid rows, let user fix and re-upload.
- **No thesis for a position:** Show P&L only, with a "Add thesis" prompt. Position has no health score.

**Strategy conversation → MonitorProfile (smart defaults) → Conversational refinement → Agent reads profile at runtime.**

```python
class MonitorProfile(BaseModel):
    alert_rules: list[AlertRule]
    price_cadence: str          # "daily" | "twice_daily" | "weekly"
    thesis_cadence: str         # "weekly" | "biweekly" | "monthly"
    deep_review_cadence: str    # "quarterly" | "monthly"
    strategy_weights: dict      # from strategy_to_monitor_weights()
    focus_areas: list[str]      # what the health check emphasizes
    web_search_enabled: bool
    web_search_sources: list[str]  # e.g. ["news", "sec_filings", "analyst_reports"]
```

The strategy conversation generates the default MonitorProfile. The user refines through conversation: "I want more aggressive thesis breach alerts" -> lowers the threshold. "Check thesis health weekly instead of biweekly" -> updates cadence.

#### Scheduling

Two scheduled jobs, using the FundOps scheduled-tasks framework:

- **`daily-price-update`**: Runs after market close (~4:30 PM ET). Fetches yfinance/FMP closing prices, calculates P&L, generates daily alerts (concentration, drawdown, big moves). No LLM calls. Cost: free.
- **`weekly-thesis-health`**: Runs Sunday evening. For each position with a thesis: web search + LLM scoring per assumption. Stores health snapshot for decay tracking. Generates thesis-related alerts. Cost: ~$2/run for 15 positions.
- **Manual trigger:** POST `/portfolio/check-health` runs an on-demand thesis health check for one or all positions. Available via UI "Check now" button.
