## Problem Statement
The IC Review (Judge) is the final gatekeeper before spending $1 on a research memo. It takes thesis output and decides PASS/NO_PASS. The current judge does mechanical stress-testing (70% haircuts, discount floors, return hurdles) plus an AI review via GPT-5 mini. What's missing: (1) it doesn't deeply read the thesis NARRATIVE to understand the story, (2) it's not strategy-aware, (3) it doesn't batch auto-run on the top 10 from thesis, (4) the frontend is a separate page instead of a unified thesis+IC view.

## What Makes This Cool
The judge doesn't just check numbers. It reads the thesis story, understands WHY the opportunity exists, and evaluates whether that story fits YOUR investment philosophy. A value investor's judge asks "is the discount real and sustainable?" A momentum investor's judge asks "is the trend strong enough and is the catalyst imminent?" Same thesis, different verdict based on who's reading it.

## Constraints
- **Cost:** AI review via GPT-5 mini is ~$0.05-0.10 per ticker. Auto-run on 10 = ~$0.50-1.00.
- **Speed:** 10 IC reviews should complete in under 2 minutes (can parallelize).
- **Existing code:** The mechanical stress-test logic is solid. Don't rewrite it. Augment it.
- **Thesis v2 compatibility:** Must consume the new thesis output schema (scorecard + narrative sections).
- **Soft gate:** PASS enables "Generate Memo" button. NO_PASS shows warning but user can still override.

## Premises
1. The judge is an integration + enhancement, not a rewrite. Mechanical logic stays.
2. Auto-run on top 10 from thesis. Manual trigger available for any of the 20.
3. Unified view: thesis results + IC verdicts in one page.
4. Strategy shapes both the mechanical thresholds AND the AI review's evaluation lens.
5. The AI review's job is to read the thesis NARRATIVE and evaluate whether the story holds up for this specific investor.
6. PASS gates memo spending. User can override NO_PASS with a warning.

## Approaches Considered

### Approach A: Config Override (minimal)
Wire strategy thresholds into existing judge. Swap hardcoded style_profile for strategy north_star.
- Effort: S | Completeness: 7/10
- Con: Judge logic is still value-shaped. AI review prompt is shallow.

### Approach B: Strategy-Shaped Logic with Narrative Understanding (CHOSEN)
Strategy determines thresholds + what the judge focuses on. AI review reads the full thesis narrative (opportunity summary, variant view, bull/bear case, key question) and evaluates it against the strategy profile.
- Effort: M | Completeness: 9/10
- Pro: The judge actually understands the thesis story and evaluates strategy fit.

### Approach C: AI-Generated Judge Logic
Same codegen pattern as screener. Fully custom judge per strategy.
- Effort: M-L | Completeness: 8/10
- Con: Qualitative judgment is hard to codegen. The AI review IS the judge's brain.

## Recommended Approach

**Approach B: Strategy-Shaped Logic with Narrative Understanding.**

### Architecture

### Strategy-Shaped AI Review Prompt

The key change. Instead of the current hardcoded style_profile string, the AI review prompt is built dynamically from the strategy:

```python
def _build_ic_prompt(self, thesis, strategy, mechanical_result):
    north_star = strategy.get("north_star", "")
    dims = strategy.get("dimensions", {})

    # Strategy type detection: prefer explicit field, fall back to keyword matching
    # The strategy conversation should set strategy_type explicitly (value/momentum/compounder/income/custom)
    strategy_type = strategy.get("strategy_type", "")
    if not strategy_type:
        # Fallback: infer from north_star and dimensions
        ns = north_star.lower()
        if any(w in ns for w in ["cheap", "undervalued", "discount", "value"]) or dims.get("cheapness"):
            strategy_type = "value"
        elif any(w in ns for w in ["momentum", "trend", "technical"]) or dims.get("momentum_signal"):
            strategy_type = "momentum"
        elif any(w in ns for w in ["compound", "quality", "moat", "durable"]) or dims.get("quality"):
            strategy_type = "compounder"
        elif any(w in ns for w in ["income", "dividend", "yield"]):
            strategy_type = "income"
        else:
            strategy_type = "custom"

    FOCUS_MAP = {
        "value": "Is the discount to intrinsic value REAL? Or is it cheap for a reason (declining business, secular headwinds, management issues)? Value traps are the #1 risk.",
        "momentum": "Is the trend strong enough to continue? Is the catalyst imminent or speculative? Momentum traps (trend reversals) are the #1 risk.",
        "compounder": "Is the competitive advantage durable? Will ROIC sustain over 5+ years? Paying up for quality that erodes is the #1 risk.",
        "income": "Is the dividend safe and growing? Can the payout ratio sustain? Yield traps (dividend cuts) are the #1 risk.",
        "custom": "Does this opportunity fit the investor's stated approach? What's the biggest risk to the thesis?",
    }
    focus = FOCUS_MAP.get(strategy_type, FOCUS_MAP["custom"])

    return f"""You are an investment committee member reviewing a thesis.

INVESTOR'S PHILOSOPHY: {north_star}
WHAT THEY CARE ABOUT: {json.dumps(dims, indent=2)}

THESIS NARRATIVE:
- Why this opportunity exists: {thesis['narrative']['opportunity_summary']}
- What the market is missing: {thesis['narrative']['variant_view']}
- Bull case: {thesis['narrative']['bull_case']}
- Bear case: {thesis['narrative']['bear_case']}
- Key question to resolve: {thesis['narrative']['key_question']}

THESIS SCORECARD: {json.dumps(thesis['scorecard'], indent=2)}

MECHANICAL STRESS-TEST RESULT:
- Base case return: {mechanical_result['base_return']:.1f}% (hurdle: {mechanical_result['hurdle_base']}%)
- Bear case return: {mechanical_result['bear_return']:.1f}% (hurdle: {mechanical_result['hurdle_bear']}%)
- Discount: {thesis['discount_pct']:.0f}% (floor: {mechanical_result['discount_floor']}%)
- Mechanical verdict: {mechanical_result['verdict']}

YOUR JOB: {focus}

Evaluate:
1. STORY COHERENCE: Does the thesis narrative make logical sense? Is the "why cheap" convincing?
2. STRATEGY FIT: Does this match what this specific investor wants? Score 1-10.
3. TRAP RISK: What could make this a trap? LOW/MEDIUM/HIGH.
4. KEY QUESTION: How critical is the unresolved question? Does it kill the thesis or reduce conviction?
5. VERDICT: PASS (worth spending $1 on full memo) or NO_PASS (not worth it for this investor)
6. CONVICTION: 1-5 scale
7. KEY ASSUMPTIONS: 3-5 things to monitor if this becomes a position

Return JSON only. No markdown."""
```

### Override Decision Matrix

| Mechanical | AI | Final Verdict | Condition |
|---|---|---|---|
| PASS | PASS / AGREE | **PASS** | Numbers and story both check out |
| PASS | NO_PASS | **NO_PASS** | AI sees narrative problems numbers don't catch |
| NO_PASS | AGREE | **NO_PASS** | Numbers fail, AI agrees |
| NO_PASS | PASS | **PASS** | Only if bear return >= 90% of hurdle (near-miss) |

### Batch Execution

```python
IC_SEMAPHORE = asyncio.Semaphore(5)  # Max 5 concurrent LLM calls

async def run_ic_single(ic_agent, ticker, db, strategy):
    """Run IC for one ticker with rate limiting and retry."""
    async with IC_SEMAPHORE:
        thesis = db.get_latest_runs("thesis", ticker=ticker, limit=1)
        if not thesis:
            db.record_run("ic_review", ticker, status="IC_PENDING", summary="No thesis found")
            return None
        try:
            result = await ic_agent.run({
                "thesis": thesis[0]["full_output"],
                "strategy": strategy,
            })
            # Persist to DB
            db.record_run(
                agent="ic_review", ticker=ticker,
                verdict=result.data["verdict"],
                scores={"conviction": result.data["conviction"], "strategy_fit": result.data["ai_review"]["strategy_fit"]},
                summary=f"{result.data['verdict']} (conv {result.data['conviction']}/5)",
                full_output=result.data,
            )
            return result
        except Exception as e:
            # Retry once
            try:
                result = await ic_agent.run({"thesis": thesis[0]["full_output"], "strategy": strategy})
                db.record_run("ic_review", ticker, verdict=result.data["verdict"], full_output=result.data)
                return result
            except:
                db.record_run("ic_review", ticker, status="IC_FAILED", summary=str(e))
                return None

async def run_ic_batch(tickers, strategy, ic_agent, db):
    """Auto-run IC review on top N thesis results. Default top 10."""
    tasks = [run_ic_single(ic_agent, t, db, strategy) for t in tickers]
    results = await asyncio.gather(*tasks)
    return [r for r in results if r is not None]
```

### Thesis v2 Interface Contract

The IC Review agent expects these fields from the thesis v2 output:

```python
# Required fields (IC Review will fail without these)
thesis["ticker"]                          # str
thesis["expected_return"]                 # float (%)
thesis["discount_pct"]                    # float (%)
thesis["return_sources"]                  # dict: {discount, growth, margin, dividends}
thesis["scorecard"]                       # dict: {dimension: {score, detail}}

# Required for AI narrative review
thesis["narrative"]["opportunity_summary"]  # str
thesis["narrative"]["variant_view"]         # str
thesis["narrative"]["bull_case"]            # str
thesis["narrative"]["bear_case"]            # str
thesis["narrative"]["key_question"]         # str

# Optional (graceful degradation if missing)
thesis["quality"]                          # dict: {gross_margin, roic, roe, debt_equity}
thesis["sec_context"]                      # dict: {filing_type, key_excerpts}
thesis["fair_value"]                       # dict: {low, mid, high}
```

Each narrative field is truncated to 500 chars max in the IC prompt to control token count (~1500 input tokens per review).

### Unified Frontend: Thesis + IC Review Page

The IC Review page goes away as a separate page. Instead, the Thesis page shows everything:

```

└─────────────────────────────────────────────────────────┘

Expanded row shows:
- Thesis narrative (opportunity, variant view, bull/bear)
- IC reasoning (story coherence, strategy fit, trap risk)
- Key assumptions to monitor
- [Generate Memo $1] button (enabled on PASS, warning on NO_PASS)
```

**Key UX decisions:**
- Strategy fit score (1-10) is a new column. Shows at a glance how well this matches YOU.
- Conviction stars are visual shorthand. 5 stars = "slam dunk for your strategy."
- NO_PASS rows are dimmed but not hidden. User can still click "Generate Memo" with a confirmation: "IC Review didn't pass this stock. Generate memo anyway? ($1)"
- Expand any row to see the full thesis narrative + IC reasoning side by side.

|---------|----------|
| Thesis not found for ticker | Skip ticker in batch. Show "No thesis" in UI. |
