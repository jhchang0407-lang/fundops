# Harness-Backed Model Providers

The AI gateway gains a provider seam: `openai` (direct API with key), `agent_cli` (the user's coding-agent harness — Claude Code, Codex, or a custom command — invoked headlessly, authenticated by the harness's own subscription), and `stub` (deterministic offline). This removes the hard API-key requirement: FundOps can run its model work through the agent session the user already pays for. Provider choice is strictly explicit opt-in — FundOps must never silently spend a coding-agent subscription just because its binary is on PATH — and tests force the stub provider by environment override.

Structured outputs stay comparable across providers because the contract never moved into the provider: every call carries a JSON shape hint, and deterministic validation (artifact schemas, guardrails, monitoring-plan validation, IC gate arithmetic) accepts or rejects the output regardless of which model produced it. Provider adapters only normalize transport (CLI flags, output envelopes, usage metadata); they do not get their own schema dialects. Execution provenance records the provider and harness for every call, and bounded repair loops handle per-provider formatting quirks.

This decision extends ADR-0050 but narrows its boundary deliberately: the harness becomes a *model provider* behind the existing gateway, not an orchestrator with write access. Workflow sequencing, stage selection, validation, and persistence remain owned by FundOps' deterministic Python layer; the harness produces candidate structured outputs exactly as the OpenAI path does. Deeper agent-session orchestration — multi-agent fan-out for memo sections, harness-driven research with tool use, file-based Agent Work Orders for a live interactive session — remains a design direction layered on the same contract, deferred until the CLI provider proves the seam.
