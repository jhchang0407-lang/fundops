# Robustify the Financial Data Pipeline Without Replacing It

FundOps will strengthen the existing Financial Data Pipeline incrementally through better concept mapping, supported-metric cataloging, validation, provenance, and coverage-gap handling rather than redesigning the pipeline or creating parallel per-workflow data paths. The current shape is already valuable: reported financial data becomes calculated fundamentals, market data supplies price-dependent context, and downstream workflows consume the shared results. We chose this because the goal is higher robustness and fewer lost datapoints, not extra complexity or a new architecture that would make screening, memo evidence, thesis health, and learning harder to audit consistently.

The first implementation slice should stay inside the current SEC/yfinance-centered pipeline: expose already calculated metrics consistently, tighten formulas and provenance where needed, add governed AI-assisted mapping for missed reported fields, and retain coverage gaps. New providers, broad architecture changes, or parallel data paths should wait until a specific gap cannot be solved responsibly through the existing pipeline.

Financial Coverage Gaps should be retained internally by default and surfaced to users only when they materially affect a workflow result, such as an unevaluable hard screen, lower evidence quality, or an unavailable metric that would otherwise explain the output. FundOps should be honest about material gaps without turning ordinary use into a data-debug console.

Financial data sources should keep clear roles inside the existing pipeline. Company filings and SEC-derived data are the primary Reported Financial Source for statements, taxonomy definitions, ratios, and filing evidence. yfinance-style sources are Market Data Sources for prices, market capitalization, volume, beta, and price history rather than authoritative reported fundamentals. Optional paid or external providers may act as Financial Enrichment Sources for estimates, peers, analyst context, and forward-looking inputs, but they should not become required for the core financial data pipeline without a specific unresolved gap.

For now, data-pipeline robustness documentation should stay at the principle level: strengthen the current SEC/yfinance path rather than redesigning it, make Supported Financial Metrics globally available with clear provenance, and use governed AI-assisted mapping to recover missing reported data before proxying. Metric-by-metric formula specs and implementation sequencing can be deferred until actual implementation work begins.
