# Bulk-First Provider Ingestion, Live APIs Reserved for Interactive Evidence

FundOps will source breadth data from official bulk products instead of per-company API calls: SEC `companyfacts.zip` for reported fundamentals (one bootstrap download, weekly or on-demand refresh), SEC daily index files (~1-3MB/day) for filing detection, SEC quarterly insider/institutional data sets for ownership evidence, and batched price-history downloads for the universe. The default Screened Universe scope becomes Russell 2000. Live provider calls are reserved for interactive evidence work — full filing text for memos, fresh quotes during interactive runs, and targeted per-company top-ups when the daily index shows a new filing before the next bulk refresh.

This collapses the previous per-capability refresh model into one daily data-sync tick: the index files tell FundOps exactly who filed, which drives financial-fact top-ups, eager recalculation, and thesis-health recalculation for precisely the affected tickers; the same tick updates price history and portfolio P&L. The weekly thesis-health metadata check and the separate daily price refresh are subsumed, and screening ~1,900 names becomes local computation instead of thousands of rate-limited calls.

Retention is split by ownership: raw bulk dumps live in a cache directory outside the workspace database and workspace archives because they are rebuildable source material (ADR-0027, ADR-0049); only universe-scoped, decision-relevant rows (facts within the lookback window, prices, filings index, ownership for known entities) land in workspace tables with normal source records and supersession. Kaggle-style static dumps were rejected: unversioned snapshots with unknown corrections and survivorship bias are weak Evidence Source Records for a provenance-first product, and batched provider downloads already cover the needed history.
