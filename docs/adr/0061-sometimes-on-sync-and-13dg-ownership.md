# Sometimes-On Sync: Catch-Up on Launch, OS-Scheduled Headless Sync, and 13D/G Ownership

FundOps assumes the app is not always running. Data freshness therefore has three legs: the in-app scheduler runs its first pass immediately on launch and catches up all daily index files since the last recorded sync day (capped at thirty days — a week offline means seven small index downloads, then targeted top-ups for exactly the tickers that filed meanwhile); a headless CLI entrypoint (`python -m backend.sync`, `npm run sync`) lets cron or launchd own wall-clock scheduling so data stays current even on days the app never opens; and manual sync remains available from Settings. Missed *workflow* work still never auto-resumes across sessions (CONTEXT's Abandoned Workflow Work rule) — catch-up applies to data ingestion only, which is cheap, idempotent, and side-effect-bounded to recalculation of affected state.

Beneficial ownership joins the ownership evidence family through Schedule 13D/13G filings, which the daily index already surfaces for known entities and which are structured XML since December 2024. Each schedule's reporting persons (name, shares, percent of class) are parsed best-effort into beneficial_ownership records; the "largest holders" view is the latest position per reporting person. An unparseable schedule remains retained as a filings-index event — parsing failures never lose the filing. S-3 and S-4 registration statements are also retained in the filings index, explicitly as dilution/M&A event records: they carry no ownership tables and must not be confused with ownership sources. Institutional 13F ingestion stays deferred on the CUSIP-mapping gap (ADR-0059).
