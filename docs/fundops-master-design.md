### 2.1 Strategy Profile

```python
class StrategyProfile(BaseModel):
    """The user's investment strategy. Generated by conversation, stored in DB."""
    id: int
    name: str                       # e.g. "Thomas's Value Pipeline"

    strategy_type: str              # "value" | "momentum" | "growth_compounder" | "income" | "balanced" | "custom"
    dimensions: dict                # key-value pairs of strategy dimensions

    #   cheapness / cheapness_valuation: str

    #   growth: str
    #   risk: str
    #   momentum_signal: str
    #   catalyst_type: str

    # Known agent_default keys:
    #   screener: {hurdle_pct, lenses, handoff}

    #   ic_review: {hurdle_base_pct, hurdle_bear_pct, style_profile}
    #   memo: {cost_limit_per_week, sector_specific_valuation}
    #   portfolio: {alert_triggers, description}
    #   allocator: {concentration_limit_pct, position_types}
    sector_routing: dict | None     # sector-specific overrides
    created_at: str
    updated_at: str
    is_active: bool
```

### 2.2 Return Sources (unified format)

Used by Thesis, IC Review, Library, and Allocator. One format everywhere.

```python
class ReturnSources(BaseModel):
    """Predicted return decomposition. Used across the pipeline."""
    discount_closing_pct: float | None   # gap to fair value closing over N years
    excess_growth_pct: float | None      # growth above what price implies
    margin_expansion_pct: float | None   # operating leverage materializing
    dividends_pct: float | None          # capital returns
    total_expected_return_pct: float | None
    horizon_years: int | None            # 1-5

    @classmethod
    def from_thesis_output(cls, thesis_data: dict) -> "ReturnSources":
        """Normalize from thesis output format."""
        rs = thesis_data.get("return_sources", {})
        return cls(
            discount_closing_pct=rs.get("discount") or rs.get("discount_closing_pct"),
            excess_growth_pct=rs.get("growth") or rs.get("excess_growth_pct"),
            margin_expansion_pct=rs.get("margin") or rs.get("margin_expansion_pct"),
            dividends_pct=rs.get("dividends") or rs.get("dividends_pct"),
            total_expected_return_pct=rs.get("total") or rs.get("total_expected_return_pct"),
            horizon_years=rs.get("horizon_years"),
        )
```

**Resolution of inconsistency #9:** Thesis outputs `{discount, growth, margin, dividends}`. Library uses `{discount_closing_pct, excess_growth_pct, ...}`. The `ReturnSources` model accepts both via `from_thesis_output()`. Canonical field names are the long form. Short form accepted as input aliases.

### 2.7 LibraryOpportunity (Library → Allocator)

```python
class LibraryOpportunity(BaseModel):
    """IC-passed memo from Library, formatted for Allocator consumption."""
    ticker: str
    expected_return: float
    thesis_summary: str
    ic_verdict: str             # should always be "PASS"
    assumptions: list[str]
    fair_value: float           # FairValue.primary (mid)
    current_price: float | None
    memo_date: str
    return_sources: ReturnSources
    strategy_fit_score: int | None  # from IC review

    @classmethod
    def from_archived_document(cls, doc: "ArchivedDocument") -> "LibraryOpportunity":
        """Convert Library's ArchivedDocument to Allocator's input."""
        return cls(
            ticker=doc.ticker,
            expected_return=doc.return_sources.total_expected_return_pct if doc.return_sources else 0,
            thesis_summary=doc.synopsis,
            ic_verdict=doc.ic_verdict or "UNKNOWN",
            assumptions=[a.description for a in (doc.assumptions or [])],
            fair_value=doc.fair_value_at_memo or 0,
            current_price=doc.current_price,
            memo_date=doc.created_at,
            return_sources=doc.return_sources or ReturnSources(),
            strategy_fit_score=None,
        )
```

**Resolution of inconsistency #4:** `LibraryOpportunity` was undefined. Now defined here with a constructor from `ArchivedDocument`.

**Note:** `ArchivedDocument` is defined in Library v2 design doc (`library-v2-design.md`, section 1). Key fields used by the converter: `ticker`, `synopsis`, `ic_verdict`, `fair_value_at_memo`, `current_price`, `return_sources` (as `ReturnDecomposition`), `assumptions` (as `list[FalsifiableAssumption]`), `created_at`.

## 3. Strategy Lens Builder (shared utility)

**Resolution of inconsistency #5:** Memo doc replaces `_build_strategy_lens()` with `_build_section_prompt()`, but Thesis, IC Review, and Portfolio Monitor still reference it. Resolution: extract to a shared utility.

```python
# backend/core/strategy_lens.py

def build_strategy_lens(strategy: dict | None) -> str:
    """Build a strategy-aware text directive for any agent's LLM prompt.

    Used by: Thesis, IC Review, Portfolio Monitor, Memo (via _build_section_prompt).
    """
    if not strategy:
        return ""

    north_star = strategy.get("north_star", "")
    dims = strategy.get("dimensions", {})
    if not north_star and not dims:
        return ""

    parts = ["\n--- STRATEGY LENS ---"]
    if north_star:
        parts.append(f"Investment philosophy: {north_star}")

    dim_mappings = {
        "cheapness": "Valuation emphasis",
        "cheapness_valuation": "Valuation emphasis",
        "quality": "Quality emphasis",
        "roic_quality": "Quality emphasis",
        "margin_quality": "Quality emphasis",
        "growth": "Growth perspective",
        "risk": "Risk tolerance",
        "momentum_signal": "Momentum/technical emphasis",
        "catalyst_type": "Catalyst focus",
    }

    for dim_key, label in dim_mappings.items():
        if dims.get(dim_key):
            parts.append(f"{label}: {dims[dim_key]}")

    parts.append("Adapt your analysis to match this strategy.")
    parts.append("--- END STRATEGY LENS ---")
    return "\n".join(parts)
```

Each agent imports `from backend.core.strategy_lens import build_strategy_lens`. Memo additionally uses it inside `_build_section_prompt()` which wraps it with section-specific depth/focus.

## 4. Agent Archival Contract (Library Integration)

**Resolution of inconsistencies #6 and #7:** Library feedback loop and archival hooks were one-sided. Here's the two-sided contract.

### Every agent that produces research output MUST:

```python
# At the end of run(), after producing output:
from backend.agents.library import LibraryIngest

async def run(self, context: dict) -> AgentResult:
    # ... agent logic ...
    result = AgentResult(...)

    # Archive to Library
    if self.library_ingest:
        await self.library_ingest.on_agent_complete(
            agent=self.name,
            ticker=ticker,
            output=result.data,
        )

    return result
```

**Agents that archive:** Thesis, IC Review, Memo (3 agents).
**Agents that DON'T archive:** Screener (too shallow), Portfolio Monitor (not research), Allocator (recommendations, not research), Library (is the archive).

### Every agent that can consume Library context MUST:

```python
# At the start of run(), check Library for prior research:
library_context = None
if self.library:
    library_context = await self.library.get_library_context(ticker)

# Use in prompt:
if library_context and library_context.researched_before:
    prompt += f"\nPrior research: {library_context.latest_thesis.synopsis}"
    prompt += f"\nPerformance since: {library_context.performance_since_research}"
    if library_context.bias_adjustments:
        prompt += f"\nBias adjustments: {library_context.bias_adjustments}"
```

**Agents that consume Library context:** Screener (prior research flag), Thesis (prior thesis to build on), IC Review (prior verdicts + bias adjustments), Allocator (opportunity pipeline).

## 7. FundOps Architecture Pattern

Every agent in FundOps follows the same three-layer pattern:

### Layer 1: AI Generates Rules (from strategy)

The strategy conversation generates deterministic configuration for each agent. This happens once (with refinement). The AI writes the rules, it doesn't run them.

- Screener: AI generates Python scoring code
- IC Review: AI generates threshold values and evaluation criteria
- Memo: AI generates MemoProfile (section depths, focus areas)
- Portfolio Monitor: AI generates MonitorProfile (alert thresholds, health weights)
- Allocator: AI generates AllocationSpec (position types, concentration limits, swap thresholds)

### Layer 2: Deterministic Execution (rules handle the math)

The generated rules run without LLM calls. Cheap, fast, reproducible.

- Screener: scoring code evaluates 1000+ stocks in seconds
- IC Review: mechanical stress-test (70% haircuts, discount floors)
- Memo: prompt builder constructs section prompts from MemoProfile
- Portfolio Monitor: alert evaluation, P&L calculation
- Allocator: constraint evaluation, swap math, concentration checks

### Layer 3: AI Narrates and Reasons (for qualitative decisions)

Where judgment is needed, the LLM provides reasoning. This is the expensive layer.

- Thesis: SEC filing analysis + web research → narrative
- IC Review: AI reads the thesis story and evaluates strategy fit
- Memo: LLM generates each section from the profile-driven prompt
- Portfolio Monitor: LLM scores assumption health against evidence
- Allocator: LLM explains why a swap makes sense for THIS investor's strategy
- Library: LLM generates post-mortem narratives comparing predicted vs actual

### Structured Output Everywhere

Every LLM call returns a typed Pydantic model. No freeform text parsing.

## 8. Build Order

Agents have dependencies. Build in this order:

### Phase 1: Foundation (no agent dependencies)

1. **Strategy Profile schema** in DB + API
2. **Shared schemas** (ReturnSources, FairValue, build_strategy_lens)
3. **Screener v2** (reads strategy, no upstream agent dependency)
4. **CSV Import + Portfolio data model** (reads CSV, no agent dependency)

### Phase 2: Discovery Pipeline

5. **Thesis v2** (consumes Screener output)
6. **IC Review v2** (consumes Thesis output)
7. **Memo v2** (gated by IC verdict, consumes its own data)

### Phase 3: Portfolio + Archive

8. **Portfolio Monitor v2** (consumes CSV data, thesis from IC output)
9. **Library v2** (consumes Thesis/IC/Memo output, needs pipeline working)

### Phase 4: Decision Engine

10. **Allocator v2** (consumes Portfolio Monitor feed + Library opportunities)

### Phase 5: Learning Loop (data accumulates over time)

11. **Library autopsy engine** (needs 3+ months of archived data)
12. **Bias detection** (needs 50+ post-mortems)
13. **Bias injection into Scout/Judge/Val** (needs bias profile)

## 12. Open System-Level Questions

1. **Error propagation.** If the Screener fails mid-run, does the Thesis batch still trigger? Proposed: no. Each trigger checks upstream status before running.
2. **Concurrent pipeline runs.** Can two tickers be in different pipeline stages simultaneously? (Yes, they should be. The pipeline is per-ticker, not global.)
3. **Multi-strategy support.** Can a user have multiple active strategies? (Not in v2. One active strategy at a time. Deferred.)
4. **Undo/rollback.** Can a user undo a conversational refinement? (Version history exists on all profiles. "Reset to version N" is possible but not designed yet.)

## Success Criteria

- All 7 agents can be built from their design docs + this master doc without asking clarifying questions about cross-agent interfaces
- The trigger chain (Screener → Thesis → IC → Memo → Library → Allocator) works end-to-end
- Changing the strategy recompiles all agent profiles and produces different output
- The Library feedback loop (bias adjustments in Judge/Val prompts) works after 50+ post-mortems
- Total system cost stays under $100/month for active single-user use
- A new developer can read this doc + 7 agent docs and understand the entire system
